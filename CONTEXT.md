# HeavenOS — the build loop

The repeating unit is **a subsystem taken from math to code**. Seven records — two grew out of splits, when a record's scope proved too broad for one four-stage loop (`symphony` → `-kernel`/`-lang`, `ftg` → `ftg`/`crystallisation`). Each runs the same four stages against the same factory.

```
_mkb/ + _spec/  ──the factory, configured once──┐
                                                ▼
   01_derive → 02_design → 03_tests → 04_implement → neos/
        ▲            ▲          ▲            ▲
        └── a human reads the output at every arrow ──┘
```

## The four stages

| Stage | Job | Input | Output | Human check |
|---|---|---|---|---|
| `01_derive` | extract the binding law | `_mkb/` + this subsystem's PRD sections | `math-contract.md` | are the open questions load-bearing? |
| `02_design` | types and interfaces | 01's output | `design.md` | can any type hold an axiom-forbidden value? |
| `03_tests` | physics assertions, first | 02's output | `test-plan.md` | would a classical implementation still pass? |
| `04_implement` | write the code | 03's output | `implementation-log.md` + code in `neos/` | tests green, deviations written down |

Factory (stable, every subsystem): `_mkb/`, `_spec/`
Product (new each subsystem): each stage's `output/`, and `neos/`

## Status is whatever exists

A stage is COMPLETE when its `output/` holds files other than `.gitkeep`. Frontmatter `stage:`/`status:` in each record is a convenience; **the filesystem wins** if they disagree.

Don't read the table below for current state — generate it:

```bash
python _system/status.py
```

The three joins that were open are now closed:

- **`substrate::MemoryPool::resolve_path`** takes a `lattice::AddressPath` and returns a real `LatticeAddress` in the pool, or refuses — `SubstrateError::Unmapped` if the named cell exists in the lattice but not in this pool, `SubstrateError::AddressUnresolvable` if the path's `(x)`-fold left the domain. ## Distillation is not enough — synthesise

The corpus **names things it never defines**. Reading only what is written down leaves holes where the PRD promised behaviour, and the source papers themselves do the same thing — and both records have now hit this:

| Gap | Closed by | Synthesised from |
|---|---|---|
| PRD §8 "volumetric time-crystal" | [`_mkb/timecrystal.md`](_mkb/timecrystal.md) §§1–4 | `C_H` + Tetryen geometry |
| PRD §3 phase shift + scale modulation | [`_mkb/gates.md`](_mkb/gates.md) | A2 + teardown `π` + standing-wave `±π/4` + `ξ(r)` |
| PRD §8 video (the other half of §8's audio/video reading) | [`_mkb/timecrystal.md`](_mkb/timecrystal.md) §5 | holographic per-frame energy + `§§1–4`'s own VTC procedure, unmodified |
| The undistilled corpus's `ψ_{n+1}=f(ψ_n,ψ_{n-1})` Tetryen placeholder | [`_mkb/tetryen_recurrence.md`](_mkb/tetryen_recurrence.md) — two implementations, `gui::TetryenState` and `crystallisation::TetryenRecurrence` | Tetryen node dynamics + the real hyperbolic metric |

All four were **derivable by composing law that already existed**. Gate 2 needed only the observation that A2's two orientations are exactly `teardown_phase_shift` apart; gate 3's band is `(π/4)/(2π) = 1/8` from two constants already in the file; video needed only the observation that a frame reduces to the same scalar the holographic pipeline already computes, which is exactly the input `§§1–4`'s machinery already takes; the recurrence needed only an exact discrete-oscillator identity plus reusing `tetryen.md`'s own node envelope as the coupling weight, rather than the fabricated `ξ(r)`, invented "hyperbolic Laplacian," and unsourced coherence formula a conversation-borne proposal offered as "settled" first. None needed new physics — all four needed someone to compose facts sitting next to each other, and the fourth needed that composition checked against a proposal that looked like law and wasn't.

The discipline that keeps this honest:

1. **Every step is a composition of existing law**, never an invention.
2. **Evaluated, not asserted** — each synthesis carries its numeric verification inline.
3. **New law goes to `_mkb/`**, upstream of the contract that needed it, never into the crate.
4. **Where composition genuinely doesn't reach, record the gap.** `{5,4}`-in-H⁴ still has no rank-4 Schläfli symbol, and guessing one would be the failure this rule exists to prevent.

Synthesising gate 3 also surfaced a **defect in shipped code**: `ξ` returned `+inf` above `r ≈ 710.5`, violating the boundedness the law states and relies on for clock-path safety. The guarding test swept `r ∈ [0, 30]`, where the bug does not appear. Composing law forces questions at the edges of a function's domain that distillation never asks.

Synthesising video surfaced a related mistake, this time caught before it shipped: the first video test used the same per-pixel amplitude the audio tests use, and every mode — including the fundamental — quantised to exactly zero. `crystallise`'s `input_energy` squares an already-squared per-frame quantity, so an audio-scaled amplitude undershoots `C_H` by another ~30 orders of magnitude. Found by printing occupation counts across six amplitudes, not by reasoning about the formula's shape — the same discipline that caught `ξ`.

- ✅ **The standing waves actually stand — animated, not just amplitude at rest** — built. Every prior render (including the still `render.ppm` above) coloured nodes and bars by `amplitude` alone, which is `StandingWave::at(x, t)` evaluated only at `t = 0` — the report has never shown the "wave" part of "standing wave." `neos/src/render.rs::render_animation` samples 24 points across one real period, at `x0 = pi/(2k)` where `sin(k*x0) = 1` so `wave.at(x0, t) = 2*amplitude*cos(omega*t)` exactly, reusing `TetryenVisualisation::at`/`LoadVisualisation::at` rather than re-deriving the formula. `neos/src/gif.rs` is a hand-written GIF89a encoder to play it back, since nothing in this workspace had ever needed one. Its first version was wrong in a way only an independent decoder caught: it assumed a fixed-width LZW code stream was safe as long as no code *referenced* a multi-symbol dictionary entry — but a real decoder grows its dictionary (and expected code width) after *every* code, unconditionally, regardless of what the encoder intended, so the stream silently desynchronised (Pillow: "broken data stream" — correct header, corrupt pixel data). Fixed by emitting a `Clear` code before every single pixel, which is provably safe rather than merely plausible: a decoder never adds a table entry for the first code after `Clear`, so with a `Clear` in front of each pixel the dictionary never grows and the code width never has to change — sidestepping GIF's LZW "early change" quirk entirely rather than trying to replicate it from memory. Re-verified against Pillow after the fix: correct frame count, correct per-frame duration, and real per-frame pixel differences confirming actual motion, not a stuck frame.

Verified as real recovery, not a demonstration of one: the retried allocation actually succeeds against real pool state.
